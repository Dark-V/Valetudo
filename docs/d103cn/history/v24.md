# v24: historical cleaning type and tray-maintenance acknowledgement

History now exposes the actual vacuum/mop type saved in ExtendData.mooClean (0 combined, 1 mop, 2 vacuum), separately from the task's whole-home/rooms/zones mode. No type is inferred from current settings or water-tank attachment. Missing, malformed or unsupported extended fields produce Unknown without discarding the record. Sequential dry/wet phases can remain separate native records.

Adds an explicit Tray cleaned button for the known code-114 reminder. The factory MsgClean constructor binds ActClearWarn as action 3; its handler accepts piid 10 as a JSON string, matching the Dreame clear_warning command. Only [114] is allowed. The handler refreshes actual state, requires docked/charging and no unfinished task, serializes requests, disables replay and verifies disappearance by fresh native reads. It does not optimistically hide the message or reset mop lifetime. GET requests and constructors never acknowledge maintenance.

Physical cleaning was hypothetical in the owner's question. No actual acknowledgement is sent by the agent during development/installation; live clearance remains for the owner to exercise after cleaning the tray. Static factory analysis, type/lint checks and read-only history/UI validation are separate from that unperformed action test.
