# v26: clickable room-profile map toolbar

The map ActionsContainer intentionally has pointer-events: none so empty overlay space passes touches to the map. Existing ActionButton controls explicitly restore pointer events, but the new standard checkbox/link row did not. Accessibility activation could toggle it while real coordinate clicks passed through, so the prior editor/API checks missed this path. The profile row now opts into pointer events and limits its hit area to fit-content; the remainder of the map overlay is unchanged. No robot-command, profile persistence or Wi-Fi behavior is changed.

The failure was reproduced on the real installed v25 with a coordinate click that left the checkbox unchanged. Verification must use actual coordinate clicks on the checkbox and Edit profiles link, not only accessibility activation. No cleaning or station command is required for this check.
