# v25: room profiles and Wi-Fi configuration

Room profiles are stored atomically under /data/.valetudo/room-profiles.json, keyed by native map and room IDs. The editor requires a recent live map and rejects stale revisions, duplicate IDs and out-of-range settings. Each enabled profile supplies fan, water and 1-3 passes through the standard Dreame selects command when cleaning selected rooms. Rooms without profiles retain global settings; whole-home and zone cleanup are unchanged. UI, API and timer room jobs share the same capability. This is Valetudo profile storage, not a writer for native customeClean/map metadata. Native customized mode is read before using profiles and must be off because it can override selects. GET /preview computes the real current request without sending it.

Wi-Fi uses the existing WifiConfiguration and WifiScan interfaces. Status and nearby-network cache reads do not force a radio scan. The UI accepts 2.4 GHz WPA2; the native MJAC shell parser limits supported SSIDs to ASCII without quotes, backslash, dollar/backtick or edge spaces. The original passphrase is not persisted: a derived PSK and the required raw-PSK MJAC marker are saved with root-only permissions. A derived PSK is still a network credential, not encrypted storage. Router internet isolation is not changed.

Only explicit Save confirmation queues a detached worker. It holds the autostart marker, stops Valetudo and waits for the existing SDK supervisor to finish restoring protected files before replacing Wi-Fi settings. New connection has a 90-second window; failure restores the previous configuration and waits 60 seconds, then attempts the stock AP at 192.168.5.1. It restarts the app with the actual new address. SSH files, rootfs, tokens and AVA are not modified; no factory reset or SDK restart is invoked. Connection loss does not cancel the worker. Do not power off during the transaction. A power interruption or failed native network driver is not claimed to be recoverable automatically. Existing SSH address restrictions remain.

Static backend/frontend checks and production frontend build passed. The detached worker was checked with the real BusyBox shell parser but was not executed. Native customized mode 4/26 read back zero. Actual Wi-Fi switching/fallback and physical cleaning using profiles remain untested; the installed read-only UI/API and profile persistence checks will be recorded separately.
